### Автор: Форш Николай

### Дата: 2026-01-03

### Use Cases

| № | Кто → Где                         | Что                                                  |
|:-:|:----------------------------------|:-----------------------------------------------------|
| 1 | Оператор КЦ → Система КЦ          | Видит актуальные ставки.                             |
| 2 | Оператор КЦ → Клиент              | Консультирует по ставкам.                            |
| 3 | Партнёрский КЦ (внешний)          | Получает файл со ставками по e‑mail.                 |
| 4 | Оператор партнёрского КЦ → Клиент | Консультирует по ставкам из файла.                   |
| 5 | Бэк‑офис                          | Обновляет ставки (как сейчас) → публикуем в витрину. |

### НФТ (минимум)

- Единый источник ставок; версии/дата.
- Внутренний КЦ обновляется быстро (минуты); партнёр — по расписанию.
- Безопасность: HTTPS внутри; файл партнёру шифруем (PGP/ZIP).
- Ретраи/журналы/алерты; простые технологии (Java/.NET, MS SQL/Oracle).

### Решение

- Сервис ставок — один источник: импорт из Excel/АБС → витрина.
- Внутренний КЦ: читает через Rate API (read‑only), локальный кэш.
- Партнёрский КЦ: экспорт CSV/XLSX по расписанию → e‑mail с шифрованием; архив и контроль доставки.
