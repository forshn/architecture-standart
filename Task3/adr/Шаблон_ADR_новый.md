| №  | Требование                                                      |

| N5 | Технологии, что уже есть: MS SQL/Oracle, Java/.NET.             |
| N6 | Масштабирование: ИБ/сервисы горизонтально; АБС — вертикально.   |
| N7 | Логи/мониторинг; повторы запросов безопасны (идемпотентность).  |

### Решение

- C4_Context_MVP.puml — контекст
- C4_Containers_MVP.puml — контейнеры

- Новый Сервис заявок: хранит заявки, общается с КЦ и АБС через Шлюз, шлёт СМС (OTP/уведомления).
- Новый Сервис ставок: витрина/кэш ставок; сайт и ИБ берут ставки отсюда (в т.ч. персональные для ИБ).
- Интернет‑банк: показывает ставки, создаёт заявку, подтверждение через СМС‑шлюз (ядро ИБ не меняем).
- АБС: бэк‑офис открывает вклад; статусы идут через Шлюз к АБС. Прямого доступа из ИБ нет.

### Альтернативы

- ИБ → АБС напрямую — риск/нагрузка, небезопасно.
- Всё внутри ИБ — зависимость от подрядчика, сложно менять.
- Сразу много микросервисов — долго и дорого для MVP.

### Риски

- На MVP ставки могут грузиться из Excel → ошибки; потом нужна нормальная система ставок.
- 99,9% может не получиться сразу; нужен план по отказоустойчивости.
- АБС масштабируется только вертикально; защищаем кэшем и ограничением вызовов.
